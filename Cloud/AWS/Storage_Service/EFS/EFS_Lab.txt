=> Part 7 - Amazon EFS Hands-on Lab

    -> Lab Objective

        In this lab, we created an Amazon EFS shared filesystem and accessed the same filesystem from two EC2 instances located in two different Availability Zones.

        We verified that:

        -> Multiple EC2 instances can mount the same EFS filesystem.
        -> EFS is accessed over the VPC network using NFS.
        -> Each Availability Zone can have its own EFS mount target.
        -> A file written from EC2-1 can immediately be accessed from EC2-2.
        -> The file is stored in EFS, not separately on either EC2 instance.

    -> Step 16 - Understand the Mount Target

        A mount target is the network endpoint through which an EC2 instance accesses EFS.

        A mount target has an Elastic Network Interface and a private IP address inside the VPC subnet.

        Therefore:

        EC2
         │
         │ NFS request
         ↓
        Mount Target
         │
         ↓
        Amazon EFS

        The mount targets do not contain separate copies of our files.

        Both mount targets provide network access to the same EFS filesystem.

    -> Step 31 - Understand Why EC2-2 Could See the File

        The file was NOT copied from EC2-1 to EC2-2.

        Both instances were accessing the same EFS filesystem.

        Actual flow:

        EC2-1
        10.0.1.169
             │
             │ Write shared-file.txt
             ↓
        Mount Target
        10.0.1.56
             │
             ↓
                     Amazon EFS
                   shared-file.txt
             ↑
             │
        Mount Target
        10.0.2.153
             ↑
             │ Read shared-file.txt
        EC2-2
        10.0.2.184

        Therefore, the mount targets are only network entry points.

        They are not separate storage locations.


    -> Step 32 - EFS Persistence Understanding

        The files are stored in EFS rather than in the local EC2 root filesystem.

        Therefore, mounting and unmounting EFS does not itself delete the files.

        Conceptually:

        File Stored in EFS
              ↓
        Unmount from EC2
              ↓
        EFS Still Exists
              ↓
        Mount EFS Again
              ↓
        Stored File Available

        EFS and the EC2 client instances have separate lifecycles.

    -> Final Lab Understanding

        Amazon EFS provides a shared network filesystem that can be mounted by multiple EC2 instances.

        In this lab, EC2-1 and EC2-2 were placed in different Availability Zones.

        A mount target was available in each Availability Zone and provided a private network endpoint for accessing the same EFS filesystem.

        The EC2 instances communicated with EFS using NFS version 4.1 over the VPC network.

        NFS traffic was controlled using Security Groups on TCP port 2049.

        The EFS DNS name resolved to the appropriate mount-target IP for each EC2 instance.

        Both EC2 instances mounted the same EFS filesystem at /mnt/efs.

        When EC2-1 created shared-file.txt, EC2-2 could immediately access the same file because the file was stored in EFS rather than locally on EC2-1.

        Therefore, the most important practical architecture learned in this lab is:

                     EC2-1
                       │
                   /mnt/efs
                       │
                    NFS 4.1
                       ↓
                 Mount Target
                  10.0.1.56
                       │
                       ↓
                   Amazon EFS
                 Shared Filesystem
                       ↑
                       │
                 Mount Target
                 10.0.2.153
                       ↑
                    NFS 4.1
                       │
                   /mnt/efs
                       │
                     EC2-2

        EC2-1 and EC2-2 are different compute instances.

        The two mount targets are different network entry points.

        But the underlying EFS filesystem and the files stored inside it are shared.
